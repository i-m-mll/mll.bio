My friends and I are playing a game, and we have a problem. We need to flip a coin, but we haven't got one.

There's an app we could use instead – but let's be creative.

We do happen to have some six-sided dice. If we come up with the right kind of rule, dice rolls will work like coin tosses.

Let's say the numbers 1, 2, and 3 count as $\mathsf{heads}$, while 4, 5, and 6 count as $\mathsf{tails}$.

<Figure src="/series/probability-theory/assets/0-functions/coindice.svg" alt="Mapping diagram from dice to coin">
This is a *mapping diagram.*
</Figure>

Other, similar rules would work just as well.

![Alternative mapping diagram](/series/probability-theory/assets/0-functions/coindice2.svg)

Say we stick with one such rule, where half the numbers map to heads, the other half to tails. And our dice rolls are fair: each number from 1 to 6 comes up just as often as each of the others. In that case we'll reach $\mathsf{heads}$ on half our rolls, and $\mathsf{tails}$ on the other half.

We've found a way to use fair dice rolls as a *model* of fair coin flips.[^7]

## What is a function?

Our rule that converts dice rolls to coin flips is an example of a *function*.

What makes something a function? Let's get a little more abstract for just a second. Here's a function called $f$ that doesn't have to do with coins, or dice, or anything in particular:

![A generic function](/series/probability-theory/assets/0-functions/function.svg)

A function is just a way to start from one *set* of things, and reach another set. Here, we start from points in $\mathsf{X}$ and arrive at points in $\mathsf{Y}$.[^6] The *points in* $\mathsf{X}$ can also be called *elements* or *members* of $\mathsf{X}$.

No matter where we start in our *source*, a function must give us *only one* place to go in our *target*. In the current example, exactly one arrow needs to start at each of the three points in $\mathsf{X}$, and end somewhere in $\mathsf{Y}$.

We already saw two different functions, that transform fair dice rolls into fair coin tosses. The source set represented the six sides of the dice, so each function had six arrows.

<NotationCallout title="Functions">

A function $f: X\rightarrow Y$ starts from points in the source set $X$, and goes to points in the target set $Y$. We write $f(x)=y$ to say "the function $f$ reaches $y$ when it starts from $x$", or "when given the input data $x$, $f$ transforms it into the output data $y$".

Because $f$ is a function, when we write $f:X\rightarrow Y$, we're saying that for every $x\in X$, there is exactly one $y\in Y$ for which $f(x)=y$.

In mathematics, the plain arrow "$\rightarrow$" is generally used to indicate the source and target of an *entire* function, like it is in the notation $f: X\rightarrow Y$. (If you hear a mathematician talking about "*an* arrow", this is probably the kind of arrow they mean.) This *isn't* the same kind of arrow as the arrows in our diagrams so far, which start from just one point in $X$ and reach just one point in $Y$.

The arrows shown in our mapping diagrams are actually the ones *inside* a function. These are normally written down like $f: x \mapsto y$, which says the same thing as $f(x)=y$. For example, for the function in the previous mapping diagram:

$$f: x_1\mapsto y_1~~~\mathrm{or}~~~f(x_{1})=y_{1}$$
$$f: x_2\mapsto y_2~~~\mathrm{or}~~~f(x_{2})=y_{2}$$
$$f: x_3\mapsto y_2~~~\mathrm{or}~~~f(x_{3})=y_{3}$$

Bringing the two kinds of arrows together: when we write $f: X\to Y$, we mean that for every $x\in X$, there is some $y\in Y$ so that $f:x\mapsto y$.

</NotationCallout>

<StringDiagramCallout title="String diagrams: Functions">

*String diagrams* are a more visual way of writing equations that are just as formal as traditional notation.

If we forget about all the arrows inside our function $f:X\to Y$, we could collapse our last mapping diagram down into something like this:

![Collapsed morphism](/series/probability-theory/assets/0-functions/morphism1.svg)

The string diagram for $f:X\to Y$ shows the same information, but it emphasizes the function instead of the source and target sets:

![String diagram for a function](/series/probability-theory/assets/0-functions/string-morphism.svg)

Note that the arrows have become boxes, and the boxes have become *wires*.

String diagrams are often written bottom-to-top, but we'll write them left-to-right.

</StringDiagramCallout>

If the number of arrows doesn't match the size of the source set, it's not a function.

![Not functions](/series/probability-theory/assets/0-functions/not_functions.svg)

These aren't functions. The one on the left has too few arrows – where do we go from $x_3$? The one on the right has too many – if we start at $x_2$, do we go to $y_1$ or $y_2$?

Importantly, a function doesn't need to reach everywhere in the target. More than one of its arrows can end in the same place.

## Possible arrows

$\mathsf{X}$ and $\mathsf{Y}$ aren't the only source and target we could choose. Say we choose a target with three points (like $\mathsf{Y}$) but a source with only two points (unlike $\mathsf{X}$). In that case, how many ways are there to draw a function?

![All possible 2-to-3 functions](/series/probability-theory/assets/0-functions/functions.svg)

We don't need to label the sets or their points, to show all the ways we can follow the rules. Any time we have a source set with two things in it, no matter what they are, and we want to choose a function that reaches a target set with three things in it, no matter what they are, those are the 9 different *mappings* – combinations of arrows – we could possibly choose.

<InfoCallout title="Number of possible functions">

Say we have a target set with $M$ elements. A function contains one arrow for each element in the source, with $M$ possible choices about where that arrow should reach. So if the source set has two elements, then there's a total of $M\times M$ (or, $M^2$) functions we could choose. And if the source set has $N$ elements, then there are $M^N$ possible functions.

Dice have six sides and a coin has two, so there are $2^6=64$ rules we could choose about how to turn dice rolls into coin flips. That also includes the "unfair" rules, though. For example, one of those rules turns all six sides into `heads`, which is probably not a rule we want to choose if we are trying to model a coin flip. Of the 64 rules we could choose, only $\binom{6}{3}=20$ of them are fair.

</InfoCallout>

Some of those mappings make more sense than others, depending on the meaning we give to the members of the sets we want to map between.

![Cats and dogs to diets](/series/probability-theory/assets/0-functions/catdog.svg)

The one on the left is clearly more valid, given the usual behaviour of cats and dogs. But what if we choose a different source set with the same size?

![Claire and Max to diets](/series/probability-theory/assets/0-functions/clairemax.svg)

Humans may be omnivorous in general, but unless you know Max and Claire already, you probably can't say which of these describes their habits better.

We can choose any source and any target, and any possible function that goes between them, depending on our purposes. At the start of this post, we wanted to turn a dice roll into a coin flip. In our last two examples, we tried to show something about the diets of some creatures.

Once we decide on the sets, the possible ways we can draw arrows only depends on the size of the source and the size of the target.

<InfoCallout title="Syntax and semantics">

Our comparison between the diagrams for $\mathsf{cats}$-$\mathsf{dogs}$ versus $\mathsf{Max}$-$\mathsf{Claire}$ is an example of a difference between *syntax* and *semantics*.

Roughly speaking, *syntax* is the way we write things down. In terms of arrows, the two diagrams the written the same way. However, the *meaning* or *semantics* of the two diagrams is clearly different.

</InfoCallout>

Of course, people don't usually draw diagrams just because they want to remember things about people, or make rules about games. But as we move forward in this series, drawing diagrams like these will help us to understand probability in terms of *following paths between collections of possibilities*.

## Composition

Why do my friends and I need to flip a coin for our game?

Because the next player only gets to move if it comes up heads!

![Go or no go from coin flip](/series/probability-theory/assets/0-functions/go_nogo.svg)

This is also a function, and it fits together with our function from earlier.

![Composing dice-coin-go](/series/probability-theory/assets/0-functions/comp_coindicego.svg)

Actually, if all we care about is starting with a dice roll and deciding whether the next player moves or not, we can forget coins were ever involved.

![Composite function](/series/probability-theory/assets/0-functions/comp_coindicego-2.svg)

Gluing together functions like this is called *composition*. It always gives another function, called the *composite*. The source of the composite is the source of the first function, and the target is the target of the second function.

Each arrow in the composite is formed by collapsing a path made from two arrows from the original functions.

![Composition arrows](/series/probability-theory/assets/0-functions/comp_coindicego-3.svg)

The composite doesn't care about what happens in between: the target of the first function, which is the source of the second function, which in this case is the set with $\mathsf{heads}$ and $\mathsf{tails}$ in it. The composite *forgets what happens in between*.

<NotationCallout title="Function composition">

Given a function $f:X\rightarrow Y$ and a function $g:Y\rightarrow Z$, their composite is $g\circ f:X\rightarrow Z$.

For example, if $f(x_1)=y_1$ and $g(y_1)=z_2$, then $(g\circ f)(x_1)=z_2$. That is:

- $f$ has $x_{1}\mapsto y_{1}$;
- $g$ has $y_{1}\mapsto z_{2}$;
- so $g\circ f$ has $x_{1}\mapsto z_{2}$.

Since $g\circ f$ is just like applying $f$ and then applying $g$, we can also write $(g\circ f)(x_1)=g(f(x_1))=z_2$, where $f(x_{1})$ is the result of $f$ that gets fed to $g$.

This notation might seem weird. We know $g$ is applied *after* $f$. If we drew one of our diagrams, $g$ would appear on the right (orange arrows). However, in $g\circ f$ it appears on the left! This reversal is related to the notation $g(f(\cdot))$.

To maintain the order seen in our diagrams, we could use the alternate notation $f\compo g: X\rightarrow Z$, where $f\compo g \coloneqq g\circ f$. (The symbol "$\coloneqq$" means "these things are equal *by definition*, and not as a result of something else".)

</NotationCallout>

<StringDiagramCallout title="String diagrams: Function composition">

In string diagrams, we can simply join functions together as we would in our mapping diagrams.

![String diagram composition](/series/probability-theory/assets/0-functions/string-comp.svg)

This is an actual mathematical equation! It says "if we input *any* $x\in X$ into $f$, then take the output of $f$ and pass it to $g$, then the output of $g$ will be identical to the output of the composite $g\circ f$ if we input the same $x$ into it as we did to $f$".

This particular diagram is a valid way to describe the composition of *any* function $f:X\to Y$ with any function $g:Y\to Z$. If we have a specific $f$ and $g$ in mind, we'll have to say so – a string diagram is more abstract, and doesn't show the internal arrows of functions like a mapping diagram would.

Sometimes, we'll omit the wire labels when the context is clear.

![String composition without labels](/series/probability-theory/assets/0-functions/string-comp-nolabels.svg)

</StringDiagramCallout>

<InfoCallout title="Squiggly arrows in mapping diagrams">

We use "$\rightsquigarrow$" in our mapping diagrams to say "we can rewrite this diagram, in this way".

Technically this is different than saying that the two sides of the diagram are equal, like we do when we use "$=$" in a string diagram equation. As mentioned in the preceding box, when two string diagrams are equal that means they represent the same computation.

If this distinction doesn't make sense, don't worry. Just consider that mapping diagrams are a less formal way we can use to write (and re-write) specific examples, while string diagrams are a more formal and general way of describing the computations involved.

</InfoCallout>

## Remembering and returning

There's one more thing we should explore in this post. What does it mean to remember the path you followed—how you arrived where you did?

We've seen that a function doesn't *need* to reach every point in its target—but some functions do. Our dice rolling function is an example: there was always some way to reach either $\mathsf{heads}$ or $\mathsf{tails}$.

![Dice to coin function](/series/probability-theory/assets/0-functions/coindice.svg)

Functions like this are called "onto"—they map *onto* the entire target. But notice something else about this function: multiple arrows end in the same place.

A function *can* have arrows that end in the same place… but some functions don't: each point they reach in their target, *they reach only once*. These functions are called *one-to-one*: there's only one point in the source that reaches any one point in the target.

Our mapping from cats and dogs to their diets is an example.

![Cats and dogs one-to-one](/series/probability-theory/assets/0-functions/catdog-2.svg)

This function is one-to-one, but it isn't onto: nothing reaches $\mathsf{herbivores}$.

If a function's source is smaller than its target, we know it won't have enough arrows to reach everywhere in the target. It can't be onto. And if a function's target is smaller than its source, then we know it can't be one-to-one—there are more arrows than there are places to go, and some must end in the same place!

<NotationCallout title="One-to-one and onto">

If a function $f:X\rightarrow Y$ is one-to-one, AKA "injective", that means no two arrows can end in the same place. If one arrow starts at $x_1$ and arrives at $f(x_1)$, and another arrow starts at $x_2$ and arrives at $f(x_2)$, then we know that $f(x_1)\neq f(x_2)$.

The rule holds whenever two arrows start at different points in $X$. So $f$ is one-to-one because for *every* $x_1$ and $x_2$ we could choose from $X$, if $x_1\neq x_2$, then $f(x_1)\neq f(x_2)$.

Similarly, if we know that $f$ is one-to-one and we find out that $f(x_1)=f(x_2)$, then $x_1$ and $x_2$ must actually be the same point in $X$, which for whatever reason we've been referring to by different labels.

If a function $f: X\rightarrow Y$ is onto, AKA "surjective", that means every point in $Y$ must be reached by some arrow in $X$. In other words, for *every* $y\in Y$, there exists some $x\in X$ for which $f(x) = y$.

</NotationCallout>

A function can be one-to-one, or onto, or both, or neither. We've already seen one that's neither:

![Neither one-to-one nor onto](/series/probability-theory/assets/0-functions/function.svg)

We don't reach every point in $\mathsf{Y}$, so we're not onto. And two arrows reach the same point, so we're not one-to-one. But *since $\mathsf{X}$ is the same size as $\mathsf{Y}$*, at least it is possible to draw a function that is both one-to-one and onto – called an *isomorphism*.

There are six possible isomorphisms from $\mathsf{X}$ to $\mathsf{Y}$.

![Six isomorphisms](/series/probability-theory/assets/0-functions/isos_xy.svg)

If our function is an isomorphism, then there's a unique match-up between points in our source and points our target. For each of the six isomorphisms above, it's easy to flip around its arrows to get an *inverse* function, which goes in the opposite direction.

![Inverse isomorphisms](/series/probability-theory/assets/0-functions/isos_xy-2.svg)

These inverses are also isomorphisms, and they are the only possible isomorphisms that go "backwards" from $\mathsf{Y}$ to $\mathsf{X}$. And because they represent unique match-ups, we could of course reverse them again to get the blue ones back.[^8]

Here's a specific example of an isomorphism: a rule that reverses the order of the numbers on our dice. When we roll a 6, we get a 1, and vice versa.

![Dice reversal isomorphism](/series/probability-theory/assets/0-functions/iso_coindice.svg)

<InfoCallout title="Reflexive functions">

In the last diagram, the set on the right is flipped upside down relative to the one on the left, to make the arrows easier to draw. But the two sets are actually identical. The function and its inverse are *reflexive* functions: they "reflect" back on the same set they start from.

For a reflexive function, the source and the target are the same, so of course they are the same size. That doesn't mean that all reflexive functions are isomorphisms, though. We could easily make a function that takes every dice roll and converts it into a 6.

![Not an isomorphism](/series/probability-theory/assets/0-functions/reflexive_coindice.svg)

This is obviously not one-to-one, and not onto. It's not an isomorphism, and we can't invert it.

</InfoCallout>

If we follow our function, and then its inverse—blue arrow, then orange—we arrive back where we started. We can also follow the inverse first—orange, then blue—and arrive back where we started, on the other side.

In either case, *an isomorphism never forgets*. And functions that aren't isomorphisms are "forgetful", in a sense. How?

What if my friends and I have the opposite problem we did yesterday? We have a coin, but no dice. Can we just reverse our function from earlier, and find another function that uses coin flips to get dice rolls?

![Cannot reverse surjection](/series/probability-theory/assets/0-functions/surject_coindice.svg)

We can't. Look at the squiggly arrows – a function can't map $\mathsf{heads}$ to 1, 2, and 3 all at once. Our function can only have two arrows, but we need six: we want the possibility of rolling any of the six sides.[^3]

If I tell you that I rolled the dice and got $\mathsf{tails}$, you have no way of knowing if I actually rolled a 4, 5, or 6. Because the dice-to-coin function isn't one-to-one, some of its arrows end at the same place, and it forgets where it started. Once we follow a blue arrow, we can't follow an orange arrow back—unlike what we could do with the isomorphism.

But just like we could with the isomorphism, we *can* follow the blue arrows back if we choose *some* of the orange arrows, and follow them first.

![Right inverse](/series/probability-theory/assets/0-functions/right_inverse_coindice.svg)

We chose to map $\mathsf{heads}$ to 2, and $\mathsf{tails}$ to 6. That won't be enough to return us to 1, 3, 4, or 5 (red points) if we follow the blue arrows first. But if we follow the orange arrows first, our blue dice-to-coin function does have the two correct arrows to convert 2 and 6 back to their respective coin flips. So while the blue function is an inverse of the orange one, the opposite is not true.

Actually, the blue dice-to-coin function can invert *any* such function we choose that converts a coin flip to a dice roll, so long as it reaches 1, 2, or 3 from $\mathsf{heads}$, and 4, 5, or 6 from $\mathsf{tails}$ – that is, so long as it respects the overall $\mathsf{heads}$-$\mathsf{tails}$ split of the blue function.

![All right inverses](/series/probability-theory/assets/0-functions/right_inverse_coindice-2.svg)

These are all of the possible *right inverses* of our dice-coin function.

<NotationCallout title="Why 'right' inverses?">

If the blue function is $f:X\to Y$ and the orange function is $g:Y\to X$, then notice that for all $y\in Y$ (that is, no matter if we start from $\mathsf{heads}$ or $\mathsf{tails}$) then $f(g(y))=y$, and we arrive back where we started.

However, for some $x\in X$ (specifically 1, 3, 4, and 5), we have $g(f(x))\neq x$.

Notice that in the first case, the one where the inverse actually works, the orange function $g$ is *on the right*: $f(g(x))$. This is just the same backwards writing that we saw when discussing composition earlier.

</NotationCallout>

<InfoCallout title="Possible functions (again)">

There are 9 functions here. We also saw 9 possible functions from a set of size 2 to a set of size 3 earlier.

That's because in both cases, there are only 3 possible places for each arrow to go. Earlier, it was because the target had only 3 points in it. Now, it's because the target is divided into 3 points for heads, and 3 points for tails, which we've colored separately – and each arrow needs to stay on its half of the split!

</InfoCallout>

So that's what happens when a function is onto but not one-to-one. What about the opposite?

![One-to-one but not onto](/series/probability-theory/assets/0-functions/inject_clairemax.svg)

We can easily invert the two existing blue arrows, *but we have no idea how to return from somewhere we never arrived* ($\mathsf{herbivores}$).[^4]

To invert our function, we have to choose one of the two squiggly arrows to follow. Let's map $\mathsf{herbivores}$ to $\mathsf{Claire}$ – an omnivore is kind of a sometimes-herbivore, I guess.

![Left inverse](/series/probability-theory/assets/0-functions/left_inverse_clairemax.svg)

The situation is opposite to what we faced when trying to invert our dice-coin function. If we follow the blue arrows first, the inverse we've chosen can return us to the same starting person, but the extra arrow we had to choose will go unfollowed (grey).

However, if we follow the orange arrows of our inverse first, $\mathsf{herbivores}$ and $\mathsf{omnivores}$ both map to Claire and there's no way for us to return to $\mathsf{herbivores}$ (red).

Here, there are only two possible *left inverses*: one maps $\mathsf{herbivores}$ to Claire, like above. The other would map $\mathsf{herbivores}$ to Max—which seems contradictory with $\mathsf{carnivores}$ already mapping to Max, though nothing about the rules of functions alone would stop us from making that choice.

Any function that is one-to-one has at least one left inverse, and any function that is onto has at least one right inverse. If a function is both one-to-one and onto it's an isomorphism, and it has only one inverse, which is both the left and the right inverse—called simply "the" inverse.

<NotationCallout title="Inverses">

If $g:X\rightarrow Y$ is a one-to-one function with at least one arrow, then there must be a function $h:Y\rightarrow X$ for which $h\comp g = \mathrm{id}_X$. In other words, if we start in $X$, then follow $g$, then follow $h$, we will arrive back at the same point in $X$ we started from. The composite of the two functions is just $\mathrm{id}_X$, which takes us from each point in $X$ to the exact same point in $X$. There may be more than one function like $h$ that works this way with $g$, and each one is a *left inverse* of $g$.

If $p: X\rightarrow Y$ is an onto function with at least one arrow, then there must be a function $q:Y\rightarrow X$ for which $p\comp q = \mathrm{id}_Y$. So the composite will return us to the identical place in $Y$, if we start from $Y$. Each function like $q$ is called a *right inverse* of $p$.

If $f:X\rightarrow Y$ is an isomorphism, then $f^{-1}: Y \rightarrow X$ is its unique inverse, and we get back to where we started, no matter which side we start on: $f^{-1}\comp f = \mathrm{id}_X$ and also $f\comp f^{-1} = \mathrm{id}_Y$.

</NotationCallout>
